# Модель оценки пасса голоса

Открытый исследовательский проект: исходная HuBERT-модель, используемая в боте,
квантованная ONNX-версия и набор голосовых признаков с человеческими оценками.
Здесь можно совместно исследовать разметку, обучать модели на признаках,
проверять способы выравнивания шкал и уменьшения модели.

Веса и данные находятся в [релизе v0.1.0](https://github.com/liya243/voice-passability-model/releases/tag/v0.1.0).

## Запуск

```bash
git clone https://github.com/liya243/voice-passability-model.git
cd voice-passability-model
pip install -e ".[onnx]"
python scripts/download_assets.py --backend onnx
voice-passability ваша_запись.wav --backend onnx
```

Для полной модели установить `.[torch]`, скачать `--backend torch` и запустить
с этим же параметром. Аудио обрабатывается на вашем компьютере.

Используются фрагменты по 5 секунд. Последний хвост короче 3 секунд
отбрасывается; 3–5 секунд дополняются до пяти. Итог — среднее оценённых окон.
Шкала 0–100 отражает субъективные человеческие оценки воспринимаемой
феминности/пасса голоса. Это не вероятность гендера и не универсальная
характеристика человека. Качество на разных голосах и условиях записи меняется.

## Датасет без аудио

9 004 вектора ECAPA размерности 192, 8 582 индивидуальные оценки,
646 настоящих оценок кластеров. Старые административные метки и 159
производных кластерных оценок явно выделены отдельно.

Оценщикам присвоены случайные шестизначные номера, общие для всех таблиц.
Номера записей и кластеров тоже случайные. Таблица соответствия, Telegram ID,
исходные имена файлов, серверные пути и даты оценок не опубликованы.

Это **псевдонимизация**. ECAPA-признаки предназначены для распознавания
говорящего, поэтому возможность сопоставлять голоса сохраняется. Отсутствие
аудио не гарантирует полную анонимность. Подробнее: [карточка данных](DATASET_CARD.md).

```bash
pip install -e ".[research]"
python scripts/download_assets.py --dataset
voice-passability-baseline --dataset data
```

Готовые ECAPA-векторы позволяют обучать регрессоры, сравнивать разметку,
выравнивать шкалы оценщиков и искать общий порядок. Для сквозного дообучения
HuBERT нужны аудиозаписи. Для собственных допустимых к использованию записей
есть пример `scripts/finetune.py`.

Разбиение train/validation/test учитывает близкие акустические группы,
но точных идентификаторов говорящих нет: независимость по людям не гарантируется.
Новые методы нужно сравнивать на одинаковых выборках и с одинаковой целевой меткой.

Будем рады pull request с воспроизводимыми экспериментами и issue с идеями.
В публичные обсуждения не прикладывайте частные аудио и идентификаторы людей.
